# v1 Routes Architecture

This directory constitutes the **Presentation Layer** of the Nexus API v1. It handles HTTP concerns, request validation via contracts, and response formatting.

## Design Philosophy

The routes layer acts as a thin adapter between the external world (HTTP) and the internal application logic (Modules).

1.  **Pure Presentation:** Routes and Controllers must contain zero business logic. They are responsible for parsing inputs, calling the appropriate Module Controller, and returning formatted outputs.
2.  **Contract-First Enforcement:** Every endpoint is bound to a schema from `@packages/nexus-api-contracts` using `createExpressController`. This ensures that both incoming requests and outgoing responses strictly adhere to the defined API contract.
3.  **Strict Layering:** Routes depend on Module Controllers. They never interact with Use Cases or Repositories directly.
4.  **Middleware Orchestration:** Authentication, Authorization (RBAC), and validation are applied at the Router level.

## 🤖 AI Agent Directives

Strict adherence to these rules is mandatory for all autonomous agents:

1.  **No Business Logic:** If you are writing an `if` statement that checks a business rule in a controller, you are in the wrong layer. Move it to a Use Case.
2.  **Contract Binding:** Use `createExpressController(contract.api.v1.<group>.<method>, ...)` for every handler. Never use standard Express `(req, res)` handlers for contract-bound routes.
3.  **Input Extraction:** Only access inputs via the `input` object provided by `createExpressController`. Do not read directly from `req.body` or `req.params`.
4.  **Error Handling:** Use `HttpError` classes (e.g., `NotFoundError`, `UnauthorizedError`) from `@/v1/errors`. Do not catch internal database errors here; let the global error loader handle them.
5.  **Router Purity:** Keep the `*.router.ts` file limited to route registration and middleware attachment. Do not define logic within the router.
6.  **Dependency Injection:** Ensure the HTTP Controller accepts the Module Controller via the constructor to maintain testability.
7.  **Output Mapping:** The `output(status, data)` function must return a payload that matches the contract response schema. Failure to do so will result in a `500 Contract Violation`.
